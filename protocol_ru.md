# Общая информация
В коде добавляется Report Id(0x00), тут он упоминаться и учитываться не будет - фича требуется для HidSharp, в других библиотеках может отсутствовать. Поэтому речь только про тот пакет что видно в Wireshark.

<details>
  <summary>Для тех кто хочет сам поснифферить, но не знает как, опишу один бесплатный вариант.</summary>

---
1. Подключаем устройство. Если речь не про сабж, то смотрим в св-вах устройства Vendor ID, Product ID.
2. Запускаем Wireshark с прослушиванием USB(USBPcap, устанавливается опционально).
3. Прописываем в фильтрах `usb.idVendor == 0x0483 && usb.idProduct == 0x5750`(в принципе хватит и PID). Смотрим пакет, и находим `Device address`(например 47, до переподключения устройства поменяться не должен).
4. Меняем фильтр на `usb.device_address == 47`, запускаем вендорское ПО(для данной станции это EasyTemp), и изучаем обмен данными. 
 
Сначала можно отловить "фоновую" активность - тогда для удобства просмотра реакции на действия с программой можно будет в фильтр накидать исключения для неинтересных команд, вроде `&& usbhid.data[0:2] != 7b:04` (получение данных о текущих Settings). Ответы на эти команды так не убрать(т.к. в ответах сразу за начальным флагом начинаются данные).

Для команд с изменением параметров проще всего, например Settings - жмём "сохранить", ловим пакет. Сохраняем данные из "HID data". Меняем какой-нибудь параметр, сохраняем, ловим пакет и сравниваем с тем что был. И так постепенно находим нужные байты для каждого параметра.

Для удобства сравнения `HID data` можно использовать табличный редактор - с помощью формул там можно раскидывать скопированные данные по байтам, и сравнивать изменения, с пометкой изменившихся байтов(для наглядности). Но можно и глазами искать.

Пакеты обмена host=\>device /  device=\>host начинаются с байта 0x7b.

В пакетах host=\>device вторым байтом идёт команда(1 байт). Блок данных заканчивается двумя байтами - 0x40 + 0x7d.

В пакетах device=\>host команды нет, и со 2-го байта начинаются данные. Блок данных заканчивается двумя байтами - 0x40 + 0x7d. В некоторых пакетах от устройства 0x407b встречается несколько раз, возможно речь идёт о нескольких блоках данных за раз.


# Некоторые идентифицированные команды
- 0x04 host=\>device, Get Settings
- 0x05 host=\>device, Get Calibrations
- 0x10 host=\>device, Set Settings
- 0x11 host=\>device, Set Callibration
- 0x30 host=\>device, Set Date
- 0x40 host=\>device, Set Interval
- 0x03 host=\>device, Get Sensors

Для экспортера использовались только 0x03, 0x30. Вообще, большая часть найденного не требуется на ПК, если не планируется собственный аналог EasyTemp(Win, Mac - Линуксу не повезло, хотя может Wine спасёт).

# Некоторые запросы и ответы

## Set Interval

host=\>device: 7b4001407d  
байт(3) - интервал записи данных датчиков в CSV файл на карту памяти, в минутах

device=\>host: 7b2f407d  
Что значит 0x2f в ответе не понятно, т.к. не зависит от отправленного значения.


## Set Settings

Настройки дисплея - то что в EasyTemp в окне Settings, кроме Interval(см. выше)

host=\>device: 7b10000c00000003000000000100000008000000400000020000001000407d

byte(2) = 0x10 - команда

byte(3) - Graph Type Temperature

- **0x00 - Temperature**
- 0x01 - Humidity
- 0x02 - Dew Point
- 0x03 - Heat Index

byte(4) - Graph Time(в общем то период отображения графики в часах, переведённый в хекс):
- **0x0c - 12H**
- 0x18 - 24H
- 0x30 - 48H
- 0x42 - 72H


byte(5) - Time Format
- 0x00 - h:mm:ss
- 0x01 - AM h:mm:ss
- 0x02 - h:mm:ss AM

byte(5) - Date Format
- 0x00 - YYYY-MM-DD
- 0x01 - MM-DD-YYYY
- 0x02 - DD-MM-YYYY

byte(7) - DST(непонятно зачем оно тут, тем более значение не сохраняется)
- **0x00 - OFF**
- 0x01 - ON

byte(8) - TimeZone, INT
- dec =\> hex 0...12H
- 256-dec =\> hex -1...-12H

byte(9) - Units
- 0x00 - C
- 0x01 - F

byte(13) - CH1
- 0x01 - Temperature
- 0x02 - DewPoint
- 0x03 - Temperature + DewPoint
- 0x04 - HeatIndex
- 0x05 - Temperature + HeatIndex
- 0x06 - DewPoint + HeatIndex
- 0x07 - Temperature + DewPoint + HeatIndex

byte(14)...byte(20) - CH2...CH8

byte(21)...byte(29) - не разобрался

byte(30)+byte(31) - флаг EoD(0x407d)



## Set Date

Установка часов на базе

host=\>device: 7b3007ea0a1b0e0b0a02407d

byte(1)

byte(2) =\> 0x30, установка даты и времени

byte(3) & byte(4) =\> комбинация значений из byte(3) и byte(4) соответствует году, т.е. 2026 год это byte(2)=0x07 и byte(3) = 0xEA

byte(5) =\> month dec=\>hex

byte(6) =\> day dec=\>hex

byte(7) =\> hours(24H) dec=\>hex

byte(8) =\> minutes dec=\>hex

byte(9) =\> secunds dec=\>hex

byte(10) = 0x02 =\> назначение в процессе сниффинга не опознано

byte(11) & byte(12) =\> флаг EoD(0x407d)


## Set Callibration

Ввод данных для калибровки сенсоров. Похоже пишется в ПЗУ, так что лучше лишний раз не писать.

host=\>device: 7b11ffecfb000000000000000000000000000000000000000000407d


byte(1)

byte(2) =\> 0x11, команда записи поправок

Дальше 8 групп(по числу каналов, в примере поправки только по одному датчику, для теста) по три байта. Первые два байта группы - температура, третий байт влажность.


Температура(t):

Для температуры от 0 и выше - простой перевод t\*10 в хекс.

Для отрицательной поправке значение получаем так: t\*10+65536, и переводим в хекс. Пример для поправки -2С:\
`-2\*10+65536 =\> 65516 =\> 0xffec =\>  первый байт группы 0xff, второй 0xec`


Влажность(h) аналогично(с учётом размера в 1 байт):

Для поправке от 0 и выше(в процентах) - простой перевод в хекс.

Для отрицательной поправки h - (h+256)=\>hex

Для поправки -5%:\
`-5+256 = 251 =\> 0xfb`

## Get Sensors

host=\>device: 7b03407d

**device=\>host: 7b010b117fffff7fffff7fffff7fffff7fffff7fffff7fffff407d0064012c0064407d000a7d696e742843292c48656174496e6465782843290d0a7d3e48b2d5**


byte(1) - как обычно(0x7b)

Дальше 8 групп(по числу каналов) по три байта.

Сначала два байта температура(как интерпретировать см. Set Callibration), потом один байт влажность(тут просто dec=\>hex).

Если сенсор не подключен, то будет 0x7fffff.

Что за данные wireshark поймал после первого включения 0x407d не разбирался.
